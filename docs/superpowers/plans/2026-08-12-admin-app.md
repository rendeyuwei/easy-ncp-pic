# EasyPic Admin App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the authenticated EasyPic administration SPA and the small API contract extensions required to manage categories and locally inspect, publish, edit, enable, sort, and delete NCP filters.

**Architecture:** A Vite 8 / React 19 application mounted at `/admin` owns session state and keeps its CSRF token only in memory. A typed API client provides single-flight session restoration and one controlled CSRF retry; TanStack Query owns category/filter server data; the browser uses `@easypic/ncp-parser` only for local inspection while Fastify remains authoritative for validation and persistence. Existing API/database repositories remain the storage boundary, with focused route-level normalization and SQLite constraint mapping.

**Tech Stack:** Node.js 22, pnpm 9.12.1, TypeScript strict, Fastify 5, SQLite/better-sqlite3, Vite 8, React 19, TanStack Router, TanStack Query, Radix Dialog, Lucide, `@easypic/ncp-parser`, Vitest, Testing Library, MSW, Playwright Chromium.

## Global Constraints

- Work on `feat/admin-app`, which starts from merged `origin/master` commit `741b851`.
- The approved design is `docs/superpowers/specs/2026-08-12-admin-app-design.md`; the parent product spec remains authoritative where the focused design is silent.
- The administration application lives only in `packages/admin-app`; it never imports `web-app` components or accesses SQLite/filesystem APIs.
- Vite asset base is `/admin/`; TanStack Router base path is `/admin`; production must rewrite `/admin/*` navigation to the administration `index.html`.
- Session cookies remain `HttpOnly`, `SameSite=Lax`, and secure according to API configuration. Passwords and CSRF tokens never enter browser storage, URLs, logs, or TanStack Query data.
- Theme preference is the only new local-storage value. Default follows the system preference and falls back to dark.
- Client NCP inspection is informational. The original bytes are sent only on save; Fastify parses, verifies support, hashes, detects duplicates, and persists its own parsed result.
- The only supported NCP layout is 638-byte NCP 1.00. The browser also rejects files over 64 KiB; Fastify's 64 KiB route `bodyLimit` applies to the complete JSON request.
- Trimmed category/filter names are `1..100` characters; descriptions are at most `500`; slugs are at most `60` and match `[a-z0-9]+(?:-[a-z0-9]+)*`; sort order is an integer.
- Create may omit a blank slug for server derivation. Edit pre-fills the current slug; a submitted slug is nonempty, and renaming never silently changes it.
- React Bits, drag sorting, bulk actions, NCP replacement, roles, analytics, and generic CRUD generation remain out of scope.
- Every behavior change follows red-green-refactor TDD and ends in a focused commit. Do not stage the pre-existing untracked `.superpowers/` directory or historical plan files.

- [ ] **Step 4: Implement shared request normalization and constraint mapping**

Create `admin-input.ts` with these public contracts:

```ts
import type { FastifyReply, FastifyRequest } from 'fastify';
import { ApiError } from '../errors';

export type AdminBodyMode =
  | 'category-create' | 'category-patch'
  | 'filter-create' | 'filter-patch';

export const SLUG_PATTERN = '^[a-z0-9]+(?:-[a-z0-9]+)*$';

export function normalizeAdminBody(mode: AdminBodyMode) {
  return async (req: FastifyRequest, _reply: FastifyReply): Promise<void> => {
    const body = req.body as Record<string, unknown>;
    for (const field of ['name', 'displayName', 'description', 'slug']) {
      if (typeof body[field] === 'string') body[field] = body[field].trim();
    }
    if ((mode === 'category-create' || mode === 'filter-create') && body.slug === '') {
      delete body.slug;
    }
  };
}

export function mapAdminConstraint(error: unknown): ApiError | null {
  const err = error as { code?: string; message?: string };
  if (!err.code?.includes('SQLITE_CONSTRAINT')) return null;
  if (err.code === 'SQLITE_CONSTRAINT_FOREIGNKEY') {
    return new ApiError(400, 'VALIDATION_ERROR', 'Invalid category', [
      { field: 'categoryId', message: 'Select an existing category' },
    ]);
  }
  if ((err.message ?? '').includes('ncp_sha256')) {
    return new ApiError(409, 'DUPLICATE_NCP', 'This Picture Control is already published');
  }
  if ((err.message ?? '').includes('slug')) {
    return new ApiError(409, 'SLUG_CONFLICT', 'This slug is already in use', [
      { field: 'slug', message: 'Choose a different slug' },
    ]);
  }
  return null;
}
```

Use `preValidation: normalizeAdminBody(...)` before route validation. Give create-name/displayName schemas `minLength: 1, maxLength: 100`; description `maxLength: 500`; create slug `minLength: 1, maxLength: 60, pattern: SLUG_PATTERN` after blank omission; patch slug uses the same nonempty schema; patch bodies use `minProperties: 1`. Keep `additionalProperties: false` and integer/boolean types.

Wrap category create/update and filter create/update repository calls. Throw `mapAdminConstraint(error)` when non-null, otherwise rethrow the original error. Delete keeps its existing `CATEGORY_IN_USE` mapping.

- [ ] **Step 4: Implement one request core and explicit method wrappers**

`AdminApiClient` owns `csrfToken: string | null`, `restorePromise: Promise<void> | null`, and an unauthorized callback. All requests set `credentials: 'same-origin'` and `Accept: application/json`; JSON requests add `Content-Type: application/json`.

Implement the mutation path with one retry flag:

```ts
private async mutate<T>(path: string, init: RequestInit, parse: Parser<T>, retry = true): Promise<T> {
  const response = await this.send(path, {
    ...init,
    headers: { ...init.headers, 'x-csrf-token': this.requireCsrf() },
  });
  if (!response.ok) {
    const failure = await this.failure(response);
    if (failure.status === 403 && failure.code === 'CSRF_INVALID' && retry) {
      await this.restoreSession();
      return this.mutate(path, init, parse, false);
    }
    if (failure.status === 401 || (failure.status === 403 && failure.code === 'CSRF_INVALID')) {
      this.clearAndNotifyUnauthorized();
    }
    throw failure;
  }
  return this.parseSuccess(response, parse);
}
```

`failure(response)` and `parseSuccess(response, parser)` each consume a response body at most once. `restoreSession()` assigns one promise and clears it in `finally`; `login()` and successful restoration replace the in-memory token. `logout()` clears the token only after `204`; any terminal unauthorized path also clears it before invoking the callback. A restoration `401` is surfaced to the session provider and does not recursively attempt another restoration.

Each public data method supplies its Task 1 singular/list response parser and unwraps `category`, `filter`, `categories`, or `filters`. Encode route ids with `encodeURIComponent`.
