# EasyPic Web App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the public EasyPic browser application that completes the local-only flow from JPG/PNG upload through Worker-backed filter preview, comparison, intensity adjustment, and original-resolution download.

**Architecture:** A Vite 8 / React 19 single-route app loads public filter data through TanStack Query and owns one `WorkerEngine` session per mounted app. Uploaded bytes move directly to the image-engine Worker; the UI keeps only the worker image handle, preview-sized pixel buffers, and downloadable encoded bytes. The responsive editor separates orchestration (`useImageSession`) from accessible presentation components so image lifecycle, render races, and URL cleanup remain independently testable.

**Tech Stack:** Vite 8.x, React 19.x, TypeScript strict, TanStack Router, TanStack Query, local shadcn/ui-style Radix components, Lucide icons, Vitest, Testing Library, MSW, Playwright Chromium, `@easypic/image-engine`, pnpm 9.12.1, Node.js 22.

## Global Constraints

- The app lives at `packages/web-app`; it calls only `GET /api/filters` and `@easypic/image-engine` and never uses administrator credentials.
- User photo bytes never enter `fetch`, `XMLHttpRequest`, form submission, or another network API.
- Accept only decodable JPG and PNG files; MIME labels are hints and the image engine remains the source of truth.
- Reject images above 10000px on either side or above 80,000,000 pixels through the existing image-engine limit.
- Default preview longest edge is 2048px; use 1280px when `navigator.deviceMemory` is present and below 4 GiB.
- Desktop uses a large preview with a fixed-width right filter rail; mobile places categories and a horizontal filter list below the photo.
- Filter intensity defaults to 100%; preview and export use the same selected `FilterParams` and intensity.
- Export defaults to the input format, supports JPG and PNG, shows JPG quality 0.92, and preserves oriented source pixel dimensions.
- Default appearance is a dark photography workspace with a light theme option and persistent theme preference.
- All critical controls are keyboard accessible, visibly focused, and labeled; reduced-motion mode removes nonessential transitions.
- React Bits is not included in this milestone: optional motion is unnecessary to the critical editor path, satisfying the requirement that it not enter the first-load path.
- API filter data uses TanStack Query with five-minute freshness; browser HTTP caching/ETag behavior remains active.
- Preview render results are request-ordered: stale asynchronous results never replace the most recent filter/intensity selection.
- Object URLs, worker image handles, and Worker/GPU resources are released when replaced or unmounted.
- Tiled export and memory-pressure downscale recovery remain a separate image-engine milestone; this app preserves editor state and gives an actionable JPG retry message when export fails.

- [ ] **Step 4: Implement pixel presentation**

`toImageData` converts each float with `Math.round(clamp(value, 0, 1) * 255)` and creates `new ImageData(bytes, width, height)`. `drawPixelBuffer` throws `Canvas 2D is unavailable` when `getContext('2d')` returns null.

- Export defaults to source format, discloses JPG 92% quality, preserves dimensions, and downloads locally.
- Desktop/mobile layouts, dark/light themes, reduced motion, focus visibility, and accessible labels pass E2E checks.
- Network assertions prove user photo data is never uploaded.
- Full workspace, image-engine browser, and web-app browser suites pass on the final tree.
